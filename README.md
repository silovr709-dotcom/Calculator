# РЕцепт — внутренний калькулятор стоимости кухонь (прайс «Висма»)

Рабочий инструмент для расчёта себестоимости и клиентской цены кухни на основе
реального прайса **«ВИСМА 2026 КХМ.xlsm»**. Все цены берутся только из прайса;
наценки, сборка, доставка и прочие параметры РЕцепта задаются в настройках и
хранятся отдельно — они не изменяют исходные цены Висмы.

## Быстрый старт

```bash
cd app
npm install
npm run dev          # открыть http://localhost:5173
```

Контрольные тесты движка расчёта (сверка с ручными расчётами по прайсу):

```bash
cd app && npm test   # 23 теста на реальных ценах
```

## Структура

| Путь | Назначение |
|---|---|
| `ВИСМА 2026 КХМ.xlsm` + файлы разбивок | Исходный прайс (первоисточник, не изменяется) |
| `tools/extract_pricebook.py` | ETL: xlsm → нормализованная база JSON + отчёт о проблемах |
| `app/public/data/pricebook-visma-2026.json` | Нормализованная база: 1747 позиций, справочники декоров, примечания, проблемы |
| `app/src/lib/engine.ts` | Расчётный движок (единицы измерения, хлысты, %, правило эмали, наценка, маржа) |
| `app/src/lib/engine.test.ts` | Контрольные тесты: количество × цена, итоги, наценка, цена клиента |
| `app/src/components/` | Интерфейс: проекты, каталог с поиском, итоги, КП, настройки, версии прайса |
| `docs/АНАЛИЗ-ПРАЙСА.md` | Полная карта структуры прайса, правила, неоднозначности (ЭТАПЫ 1–4) |

## Архитектура данных (разделение слоёв)

1. **Исходный прайс Висмы** — xlsm-файлы в корне репозитория, только чтение.
2. **Нормализованная база** — JSON, создаётся ETL-скриптом; каждая позиция хранит
   лист/строку-источник, единицу измерения, тип цены (`fixed / percent / surcharge /
   unavailable / text / empty`) и базис расчёта (`шт / м² / п.м / хлыст / % от базы`).
3. **Правила расчёта** — движок `engine.ts`: площадь из размеров, «кратно метру»,
   хлысты/полхлыста, процентные надбавки от базовой позиции, правило «эмаль < 1 м² +30%».
4. **Настройки РЕцепта** — наценка (базовая + по категориям), сборка, доставка,
   доп. расходы; по умолчанию пустые (ничего не придумано), localStorage.
5. **Проекты** — localStorage + экспорт/импорт `.json`; каждая строка проекта хранит
   **снимок цены** на момент добавления, поэтому обновление прайса не меняет старые расчёты.
6. **Клиентское представление** — печатное КП и Excel без себестоимости и наценок.

## Обновление прайса (например, «ВИСМА 2027 КХМ.xlsm»)

```bash
python3 -m pip install openpyxl
python3 tools/extract_pricebook.py "ВИСМА 2027 КХМ.xlsm" pricebook-visma-2027.json
```

Полученный JSON загружается в приложении: **Прайс и версии → «Загрузить новую версию»**.
Старые проекты сохраняют цены своего расчёта (снимки). Если структура листов нового
прайса изменится — скрипт сообщит об ошибках разбора, и их нужно поправить в ETL,
а не подгонять цены.

## Что важно знать

- Позиции «временно недоступен», с текстовой или пустой ценой не считаются молча:
  строка помечается предупреждением, сумма не выдумывается.
- Отчёт **«Проблемы исходного прайса»** (78 записей) — в разделе «Прайс и версии».
- Лист **BLUM** в исходной книге скрыт и содержит цены, отличающиеся от раздела
  Blum на листе «Доп комплект» — обе версии доступны с указанием листа-источника.
- Секретов/ключей в коде нет; приложение работает офлайн после загрузки.
