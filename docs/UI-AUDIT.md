# Расследование интерфейса: почему «вкладки заходят друг на друга»

Дата: 14.10.2026. Ветка: `arena/01a0ee6f-calculator`.
Предмет: жалоба «вкладки заходят друг на друга, отделы накладываются, кнопок много и они разбросаны хаотично».
Цель: сохранить **все** существующие функции и сделать работу комфортной.

## 2. Найденные причины (по степени вреда)

### Причина №1. Модальные окна рисуются внутри карточек — и не могут перекрыть экран

Все 9 модальных окон рендерились прямо там, где объявлены: внутри панели, внутри карточки, внутри таблицы.
При этом в стилях было:

```css
.card, .table, .totals-card, .empty, .client-doc, .dashboard-filters {
  backdrop-filter: blur(14px) saturate(1.18);
}
```

По спецификации CSS **элемент с `backdrop-filter`, `filter` или `transform` становится containing block для `position: fixed` потомков**.
Значит `.modal-back { position: fixed; inset: 0 }` внутри такой карточки растягивался **не по экрану, а по карточке**: окно вылезало поверх соседней секции, подложка закрывала кусок страницы, а не весь экран. Это и есть буквальное «окна и отделы накладываются».

Усугубляло `.main { overflow: hidden }` — контейнер обрезал всё, что выходит за его границы: выпадающие меню кнопок, поповеры, тот же залипший диалог.

### Причина №2. Шкалы слоёв не существовало

23 разных значения `z-index`, выданных «на глаз» в разное время:

| Было | Кто | Последствие |
| --- | --- | --- |
| 20 | `.dropdown-menu` | выпадающее меню уходило **под** боковое меню (70/90) и под мобильный док (120) |
| 50 / 360 | `.modal-back` (два разных правила) | порядок окон зависел от того, какое правило победило |
| 90 | `.toast` | уведомление пряталось за мобильным доком (120) |
| 320 | попап модуля | конфликтовал с каталогом (360) |
| 2499/2500/3000 | калькулятор в поле, палитра Ctrl+K | числа «про запас», ничем не обоснованные |

### Причина №3. Пять липких блоков в одном потоке скролла, без договорённости об отступах

`.eskiz-module-tabs` (top 0), `.project-mobile-switcher` (top 0), `.project-flow-rail` (top 12), `.totals-col` (top 16), `.quick-total-card` (top 12), `.project-context-panel` (top 12), шапки таблиц (sticky). Ни один не знал о высоте другого → при прокрутке они налезали друг на друга.
Отдельно: из-за `overflow: hidden` на `.main` часть «липких» блоков вообще не липла, потому что контейнер-скролл был другой — поведение выглядело случайным.

### Причина №4. На экране проекта было **четыре** навигации и **три** заголовка

`ProjectEditor` выводил подряд, до единой строки контента:

1. `page-head` — название проекта;
2. `project-command-center` — «Всё важное — в одной панели»: главное действие + меню «Разделы проекта ▾» (те же 5 этапов) + статус + отмена + «Экспорт и обмен ▾» + «Проект ▾»;
3. `project-readiness-panel` — заголовок + те же 5 этапов кнопками;
4. `editor-mode-bar` — переключатель «мастер / маршрут»;
5. `project-flow-rail` — боковая колонка 270 px: снова 5 этапов + подразделы + «назад/вперёд»;
6. `project-mobile-switcher` — те же этапы и подразделы, но двумя `<select>`;
7. `project-section-head` — ещё раз этап, ещё раз название раздела, подсказка и 4 показателя.

Итого: этап можно было переключить в **3 местах**, раздел — в **2**, главное действие дублировалось в правой панели «Контекст проекта» (ещё одна `primary`-кнопка), а до содержимого приходилось пролистывать ~500 px шапок. Плюс три колонки навигации одновременно: меню приложения (232 px) + rail (270 px) + контекст-панель (310 px) — на ноутбуке контенту оставалась половина экрана.

### Причина №5. Правила-призраки

`.sidebar` описан 48 раз, `.card` — 45, `.modal` — 44, `.tabs` — 26. Темы накладывались поколениями: тёмная «HUD»-тема, поверх неё светлая через 422 `!important`. Любая правка размера/отступа в одном месте гасилась правилом ниже по файлу — отсюда непредсказуемая геометрия и «съезжающие» блоки.

### Причина №6. Плотность действий без иерархии

77 кнопок в редакторе эскиза, 58 в панели Эскиз PRO, 49 в модулях. Проблема не в количестве функций, а в том, что **все они одного визуального веса и лежат в одном ряду**: главное действие неотличимо от служебного.

### Причина №7. Повторяющиеся сущности

Одно и то же действие вызывается из 2–4 мест (экспорт — из шапки, из меню «Экспорт», из контекст-панели, из карточки документов). Пользователь не запоминает маршрут, потому что маршрута нет — есть набор равноправных входов.

## 3. Принципы, по которым наводится порядок

Функции **не удаляются**. Меняется только то, где они живут.

1. **Одна навигация на уровень.** Приложение — боковое меню. Проект — один блок «этапы → разделы». Внутри раздела — только содержимое.
2. **Одно главное действие на экран + «Ещё ▾».** Главное — `primary`-кнопка, всё остальное — в меню с группами.
3. **Слои только из шкалы.** Никаких новых чисел: есть токены `--z-*`, внутри компонента допустимы 1..9.
4. **Оверлеи — через портал в `body`.** Модальное окно не зависит от карточки, из которой открыто.
5. **Дисциплина липких блоков.** Высота шапки известна CSS (`--project-topbar-h`), всё липкое встаёт под ней.
6. **Список → попап.** Экран остаётся списком, редактирование — во всплывающем окне (уже работает в модулях, дальше — замер, прайс, КП, CRM).
7. **Никаких `!important` в новых правилах.**

## 6. Как проверять, что порядок не разъезжается снова

1. `grep -oE 'z-index: *[0-9]{2,}' app/src/index.css` — должно быть пусто (только токены и локальные 1..9).
2. `rg 'position: fixed' app/src/index.css` — каждый такой элемент обязан рендериться через `Portal`.
3. Новые модальные окна — только через `Overlay` из `components/Portal.tsx`.
4. Новые липкие блоки — `top: calc(var(--project-topbar-h, 0px) + N)`.
5. На экране ровно одна `primary`-кнопка.
6. Новая навигация добавляется только заменой существующей, а не рядом с ней.

## 7. Аудит тач-использования (телефон и планшет) — 22.10.2026

Точка зрения: палец, без мыши и клавиатуры. Найдено и исправлено:

### Эскиз PRO (EmbeddedEskizEditor) — «невозможно пользоваться»
1. **Вид полотна двигался только пробелом+мышью или средней кнопкой** — на тач-экране
   сдвинуть эскиз было физически нечем (полотно `touch-action: none`, рамка выделения
   пальцем бесполезна). → Палец по пустому полотну теперь двигает вид.
2. **Масштаб был только колесом мыши** (Ctrl+колесо, ползунок мелкий). → Щипок двумя
   пальцами (как на картах) вокруг точки сведения; вторый палец отменяет начатое
   перетаскивание и не рисует случайные объекты.
3. **Панель действий — 9 мелких кнопок в шапке.** → «↶ ↷ Сохранить» + «Ещё ▾»
   (остальное: замена фото, буфер, импорт/экспорт, PNG/PDF).
4. **Цели нажатия 26–34px** при норме 44px. → На `pointer: coarse` инструменты,
   зум-бар, вкладки инспектора и поля — 36–44px; hotkey-подсказки (`kbd`) скрыты.
5. **Полотно и панель свойств разрезаны пополам экрана.** → На узких экранах
   один прокручиваемый столбец: полотно ~55dvh, свойства ниже.
6. **Подсказки про Ctrl+V/Пробел** — на таче своя подсказка: «палец по пустому месту —
   двигать вид · два пальца — масштаб».
7. Ручки коммуникаций (r=7–8) — увеличены до 10–11.

### Прочие экраны
8. **Пикер каталога/прайса на телефоне** — правило ≤980px возвращало две колонки
   (правая минимум 300px), на 375px экране левая сжималась до 75px. → На ≤760px одна колонка.
9. **Кнопки дня в расписании открывались только наведением мыши** (`:hover`) — на таче
   их не существовало. → На `hover: none` видны всегда.
10. Общая шкала нажатия: `.btn` 42px, `.small` 38px, `.tiny` 36px на тач-устройствах.

### Правило приёмки (добавить к разделу 6)
7. Проверка на тач: панорамирование любой рабочей области — пальцем; масштаб — щипком;
   ни одно действие не требует hover/правой кнопки/клавиатуры; цель нажатия ≥ 36px.
