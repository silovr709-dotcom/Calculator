# Пошаговый запуск калькулятора на хостинге reg.ru

Инструкция «куда зайти и что нажать». Ничего собирать на своём компьютере не нужно —
готовый архив делает GitHub. Время: 20–30 минут.

Что понадобится:

* доступ в личный кабинет **reg.ru** (логин и пароль);
* данные **FTP** (сервер, логин, пароль) — они уже у вас есть;
* доступ к репозиторию **github.com/silovr709-dotcom/Calculator**.

---

## Часть 1. Скачать готовый архив с GitHub (3 минуты)

1. Откройте **https://github.com/silovr709-dotcom/Calculator/actions**
2. В списке слева нажмите **Deploy to GitHub Pages**.
3. В таблице справа нажмите на **верхнюю строку с зелёной галочкой** (название последнего запуска).
4. Прокрутите страницу вниз до блока **Artifacts**.
5. Нажмите на **recept-site** — скачается файл `recept-site.zip` (около 2,3 МБ).
6. Пока **не распаковывайте**: если будете грузить через панель хостинга (вариант А в части 3),
   архив заливается как есть. Для загрузки по FTP через FileZilla (вариант Б) распакуете его на шаге Б3.

> Внутри архива: само приложение, папка `api` (серверная часть на PHP) и скрытые файлы
> `.htaccess`, `.user.ini` с настройками HTTPS, сжатия и лимитов.

---

## Часть 2. Подготовить хостинг в панели reg.ru (10 минут)

### 2.1. Войти в панель управления

1. Откройте **https://www.reg.ru** → **Войти** → вы в личном кабинете.
2. Раздел **Мои домены и услуги** (или **Услуги → Хостинг**) → нажмите на свой хостинг.
3. На странице услуги нажмите кнопку **Панель управления** — откроется **ispmanager**
   (если у вас cPanel или Plesk — шаги те же, названия разделов чуть отличаются, они указаны ниже).
4. Запомните **логин хостинга** — он выглядит как `u1234567` и показан на карточке услуги.

> ### ⚠ `u1234567` — это пример, а не адрес
>
> Везде в этой инструкции `u1234567` означает **ваш личный логин хостинга**: буква `u`
> и 7 цифр, у каждого свои (например `u2938471`). Подставляйте всюду свой.
>
> Где его взять: личный кабинет reg.ru → **Мои домены и услуги** → ваш хостинг —
> логин написан на карточке услуги (а также в письме «Услуга хостинга активирована»
> и в правом верхнем углу панели управления).
>
> Если открыть адрес с чужими цифрами `u1234567`, браузер покажет чужую заглушку
> или пустую страницу — это не ошибка установки.

### 2.2. Создать сайт (домена пока нет — берём технический адрес)

1. В ispmanager слева нажмите **Сайты**.
2. Если сайт уже есть — пропустите этот пункт. Если списка нет, нажмите **Создать сайт**.
3. В поле **Доменное имя** введите технический адрес:
   `u1234567.isp.regruhosting.ru` (вместо `u1234567` — ваш логин хостинга).
4. Остальные поля не трогайте, нажмите **Ok**.
5. Технический адрес начинает работать в течение нескольких часов (иногда сразу).

> В **cPanel** технический адрес `u1234567.cp.regruhosting.ru` работает сразу,
> а папка сайта называется `public_html`.

### 2.3. Поставить PHP 8

1. Раздел **Сайты** → выделите строку с сайтом → на верхней панели нажмите **PHP**
   (в старых версиях: **Изменить** → пункт «Версия PHP»).
2. Выберите версию **8.1** или **8.2** (подойдёт любая 8.x).
3. **Режим работы PHP** — выберите тот, что есть в списке. На reg.ru это обычно
   **FastCGI (Apache)**, и он полностью подходит: приложение работает в любом режиме
   (FastCGI, CGI, PHP-FPM, mod_php). Настройки размеров в файле `.user.ini` в режиме
   FastCGI читаются, а строки `php_value` в `.htaccess` специально закрыты условием,
   поэтому ошибки 500 из-за них не будет.
4. Нажмите **Ok**.

> **Если проекты с большим количеством фотографий не сохраняются** (раз в несколько
> месяцев такое возможно на строгих лимитах хостинга): приложение само сжимает данные
> перед отправкой, но предел можно поднять. Раздел **Сайты** → ваш сайт → **PHP** →
> **Настройки PHP** (или файл `.user.ini` в корне сайта): `post_max_size = 256M`,
> `upload_max_filesize = 256M`, `memory_limit = 512M`. Изменения применяются за 1–5 минут.

### 2.4. Посмотреть папку сайта

В разделе **Сайты** есть колонка **Корневая директория** — например
`/www/u1234567.isp.regruhosting.ru`. Запишите её, она понадобится в части 5.

---

## Часть 3. Загрузить файлы на хостинг (5–15 минут)

Есть два пути. **Вариант А (панель reg.ru)** — проще, ничего устанавливать не нужно,
архив распаковывается прямо на сервере. **Вариант Б (FileZilla)** — если вам привычнее FTP
или в панели не работает распаковка. Делать нужно **что-то одно**, не оба сразу.

### 3.0. Сначала поймите, куда грузить

Файлы должны лежать **в корневой папке сайта** — это та папка, содержимое которой
показывается, когда открываешь адрес сайта в браузере. Её имя зависит от панели:

| Панель | Путь к папке сайта |
|---|---|
| ispmanager (по умолчанию на reg.ru) | `/www/u1234567.isp.regruhosting.ru` |
| cPanel | `/public_html` (для основного домена) |
| Plesk | `/httpdocs` или `/domain.ru` |

Точный путь виден в ispmanager: раздел **Сайты** → колонка **Корневая директория**.
Запишите его — он нужен и для FileZilla, и для части 5.

Правильный результат загрузки выглядит так (файлы лежат **прямо** в папке сайта):

```
/www/u1234567.isp.regruhosting.ru/
├── index.html          ← главный файл, должен лежать именно здесь
├── .htaccess           ← скрытый, но обязательный
├── .user.ini           ← скрытый, но обязательный
├── api/                ← серверная часть (core.php, index.php, .htaccess)
├── assets/
├── data/
├── img/
├── templates/
├── favicon.svg
└── icons.svg
```

Частая ошибка — лишняя вложенная папка:

```
/www/u1234567.isp.regruhosting.ru/
└── recept-site/        ← ТАК НЕ НАДО: сайт откроется пустым
    └── index.html
```

### Вариант А — через панель reg.ru (рекомендую)

1. Личный кабинет reg.ru → **Мои домены и услуги** → ваш хостинг → **Панель управления**.
2. Раздел **Сайты** → выделите строку сайта → кнопка **Файлы сайта** на верхней панели.
   Откроется менеджер файлов, сразу внутри папки сайта (путь виден сверху — сверьте его с таблицей выше).
3. Если внутри лежит заглушка `index.html` (страница «Сайт создан») — выделите её и нажмите **Удалить**.
4. Нажмите **Загрузить** → **Файл с локального компьютера** → выберите скачанный
   `recept-site.zip` → **Ok**. Идёт 1–3 минуты, внизу видна полоса загрузки.
5. Выделите появившийся `recept-site.zip` → верхняя панель **Архив** (или ПКМ → **Извлечь**)
   → в поле «Путь» должна стоять **текущая папка сайта**, без добавления имени архива → **Ok**.
6. Посмотрите, видны ли в списке `.htaccess` и `.user.ini`.
   **Если их не видно — ничего страшного и искать настройку не нужно:** при распаковке архива
   они всё равно создались, просто файловый менеджер прячет файлы, имя которых начинается с точки.
   Проверить их наличие можно страницей самопроверки из п. 3.9 — она смотрит на файлы
   со стороны сервера и видит скрытые.

   > Где настройка показа скрытых файлов есть (если хочется убедиться глазами):
   > **ispmanager** — кнопка/значок **«Настройки таблицы»** или **«Вид»** над списком файлов
   > (в части версий dot-файлы показываются сразу и отдельной галочки нет);
   > **cPanel** — File Manager → кнопка **Settings** справа сверху → галочка
   > **Show Hidden Files (dotfiles)** → Save; **Plesk** — dot-файлы видны сразу.
   > В новых ispmanager такой галочки действительно нет — это нормально.
7. Сверьте видимую часть списка со схемой из п. 3.0 (`index.html`, `api`, `assets`, `data`, `img`, `templates`).
   Если всё распаковалось в подпапку `recept-site` — зайдите в неё, выделите всё (Ctrl+A),
   нажмите **Копировать/Переместить**, укажите путь папки сайта, затем удалите пустую подпапку.
8. Выделите `recept-site.zip` → **Удалить**. Архив на сервере больше не нужен.

Переходите к п. 3.9 (проверка).

### Вариант Б — через FileZilla, по шагам

#### Б1. Где взять FTP-данные

Нужны три вещи: **хост**, **логин**, **пароль**.

* Они пришли в письме от reg.ru при активации хостинга — тема вида
  «Услуга хостинга активирована», блок «Доступ по FTP».
* Либо: личный кабинет → ваш хостинг → вкладка **Доступы** / **Пароли** —
  там же можно сменить пароль, если он потерян.
* Либо создайте отдельного FTP-пользователя: ispmanager → раздел **FTP-пользователи**
  → **Создать** → имя, пароль, **Домашняя директория** — укажите папку сайта
  (`/www/u1234567.isp.regruhosting.ru`). Тогда после подключения вы сразу окажетесь
  в нужной папке и ошибиться местом будет невозможно.

Хост обычно один из: `u1234567.isp.regruhosting.ru`, `u1234567.ftp.regruhosting.ru`
или IP-адрес сервера — берите ровно то, что написано в письме/панели. Порт — **21**.

#### Б2. Поставить FileZilla

1. Откройте **https://filezilla-project.org** → **Download FileZilla Client**
   (именно **Client**, не Server; он бесплатный).
2. При установке снимайте галочки с предложений поставить «дополнительный» софт.

#### Б3. Распаковать архив на своём компьютере

1. ПКМ по `recept-site.zip` → **Извлечь всё** (Windows) или двойной клик (macOS).
2. Зайдите внутрь получившейся папки и убедитесь, что видите `index.html`, `api`, `assets`.
   Если внутри одна-единственная папка — зайдите ещё на уровень глубже, нам нужен тот уровень,
   где лежит `index.html`.

#### Б4. Включить показ скрытых файлов в своей системе

Иначе вы просто не увидите `.htaccess` и `.user.ini` в левой панели FileZilla и не зальёте их.

* **Windows 10/11:** откройте папку → вкладка **Вид** → **Показать** → галочка **Скрытые элементы**.
* **macOS:** в Finder нажмите **Cmd + Shift + точка**.

#### Б5. Подключиться

1. FileZilla → меню **Файл** → **Менеджер сайтов** → **Новый сайт**, назовите «reg.ru».
2. Заполните правую часть:

   | Поле | Значение |
   |---|---|
   | Протокол | **FTP — протокол передачи файлов** |
   | Хост | ваш FTP-хост из Б1 |
   | Порт | `21` |
   | Шифрование | «Использовать явный FTP через TLS если доступно» |
   | Тип входа | **Нормальный** |
   | Пользователь / Пароль | ваши FTP-логин и пароль |

3. **Соединиться**. Если спросит про сертификат — поставьте галочку
   «Всегда доверять этому сертификату» → **ОК**.
4. Внизу в логе должно появиться «Статус: Соединение установлено» и список папок справа.

#### Б6. Включить показ скрытых файлов на сервере

Меню **Сервер** → **Принудительно отображать скрытые файлы**.
Это нужно, чтобы в правой панели были видны файлы, начинающиеся с точки
(`.htaccess`), — иначе вы не сможете проверить, что они залились,
и при повторной заливке FileZilla не предупредит о перезаписи.

#### Б7. Открыть папку сайта (правая панель)

1. Справа вы, скорее всего, окажетесь в домашней папке, где лежат `www`, `domains`, `etc`, `tmp`.
2. Двойным кликом войдите в `www` → затем в папку с именем вашего сайта
   (`u1234567.isp.regruhosting.ru`). В cPanel это `public_html`.
3. Путь сверху в строке «Удалённый сайт» должен совпасть с тем, что вы записали в п. 3.0.
4. Если внутри лежит заглушка `index.html` — ПКМ по ней → **Удалить**.

#### Б8. Залить **содержимое** папки, а не саму папку

1. В **левой** панели (ваш компьютер) зайдите **внутрь** распакованной папки — так,
   чтобы в нижнем левом списке были видны `index.html`, `api`, `assets`, `.htaccess`, `.user.ini`.
2. Кликните по любому файлу в этом списке и нажмите **Ctrl + A** — выделится всё содержимое.
3. ПКМ по выделенному → **Закачать на сервер** (или просто перетащите выделенное
   в правую панель).

   * Правильно: вы выделили **файлы и папки внутри** распакованной папки.
   * Неправильно: вы выделили саму папку `recept-site` целиком — тогда на сервере
     появится лишний уровень вложенности и сайт откроется пустым (см. схему в п. 3.0).

4. Загрузка 500+ мелких файлов идёт 3–10 минут. Внизу видна очередь — вкладка
   **«Файлы в задании»**. Не закрывайте FileZilla до её опустошения.

#### Б9. Проверить, что ничего не потерялось

1. Внизу посмотрите вкладку **«Неудавшиеся передачи»**. Если там что-то есть —
   выделите всё → ПКМ → **Повторно добавить в задание** → меню **Передача** →
   **Обработать очередь**. Повторяйте, пока вкладка не станет пустой.
2. В правой панели сверьте список с правильной схемой из п. 3.0.
   Обязательно должны быть видны `.htaccess`, `.user.ini` и папка `api`
   (внутри неё — `core.php`, `index.php`, `.htaccess`).

> Вместо FileZilla можно пользоваться **WinSCP** или **Total Commander** —
> логика та же: подключиться по FTP, включить показ скрытых файлов,
> залить содержимое папки в корень сайта.

### 3.9. Проверка, что загрузка удалась (делается в браузере)

Откройте в браузере:

```
https://u1234567.isp.regruhosting.ru/api/index.php?r=check
```

Это **страница самопроверки**. Она проверяет сайт со стороны сервера, поэтому
**видит скрытые файлы** `.htaccess` и `.user.ini`, даже если файловый менеджер их не показывает.
Вы увидите список строк с зелёными галочками:

* версия PHP;
* на месте ли `index.html`, `assets`, `api/core.php`;
* на месте ли скрытые `.htaccess`, `.user.ini`, `api/.htaccess`;
* применяются ли настройки `.htaccess` хостингом;
* создана ли папка для данных и есть ли право на запись;
* включены ли нужные расширения PHP;
* максимальный размер сохранения;
* созданы ли учётные записи.

Сверху — общий вывод: «Всё в порядке», «есть замечания» или «есть проблемы».
Напротив каждой красной строки написано, что именно сделать. После исправления
просто обновите страницу (F5).

Когда вывод зелёный — откройте сам адрес сайта, появится экран **«Первый запуск»** (часть 4).

> Если страница `?r=check` не открывается вообще (ошибка 404), значит папка `api`
> не загрузилась в корень сайта — вернитесь к п. 3.0.

### 3.10. Если что-то пошло не так

Сначала всегда открывайте страницу самопроверки `/api/index.php?r=check` — она называет
причину сама. Ниже — расшифровка остальных случаев.

| Что видите | Причина и что делать |
|---|---|
| Пустая страница или список файлов/папок | Файлы лежат во вложенной папке. Перенесите содержимое на уровень выше (п. 3.0) |
| Всё ещё страница «Сайт создан» | Не удалена заглушка `index.html`, либо браузер закэшировал — нажмите **Ctrl + F5** |
| Сайт открывается, но после входа «Сервер недоступен» | Не залился `.htaccess` или папка `api`. Откройте `/api/index.php?r=check` — там видно, какого файла нет |
| Не вижу скрытых файлов в менеджере хостинга | Так и должно быть в части панелей. Наличие `.htaccess`/`.user.ini` проверяйте страницей `/api/index.php?r=check` |
| `404` на `api/index.php?r=health` | Папка `api` не загрузилась или загрузилась не в корень сайта |
| `500` на `api/index.php?r=health` | Версия PHP ниже 8.0 — поставьте 8.1/8.2 (п. 2.3) |
| «Нет доступной папки для данных» | Нет прав на запись. В менеджере файлов создайте папку `recept-data` **рядом** с папкой сайта и поставьте ей права `755`; либо создайте `api/config.php` с содержимым `<?php return ['dataDir' => '/var/www/u1234567/data/recept-data'];` |
| `530 Login incorrect` в FileZilla | Неверный FTP-логин/пароль (они могут отличаться от входа в панель). Смените пароль FTP в личном кабинете |
| «Не удалось получить список каталога» | FileZilla → **Редактирование → Настройки → FTP** → режим **Пассивный**; проверьте, что антивирус/файрвол не блокирует |
| `550 Permission denied` | Вы пытаетесь писать в домашнюю папку, а не в папку сайта — зайдите в `www/<адрес>` |

## Часть 4. Первый запуск приложения (3 минуты)

1. Откройте в браузере адрес сайта: `https://u1234567.isp.regruhosting.ru`
2. Появится экран **«Первый запуск»**. Заполните:
   * **Логин** — латиницей, например `vladimir`;
   * **Как вас зовут** — как будет видно коллегам;
   * **Пароль** — не короче 8 символов, и повторите его.
3. Нажмите **Создать и войти** — откроется калькулятор с пустой общей базой.
4. Проверка, что сервер отвечает: откройте `https://ваш-адрес/api/index.php?r=check`
   (наглядная страница самопроверки) или `https://ваш-адрес/api/index.php?r=health`
   (та же проверка строкой: `{"ok":true,"app":"recept-calculator",...}`).
5. Левое меню → **Сервер** → блок **Сотрудники** → заполните логин, имя, пароль, права
   («Сотрудник» для замерщика и менеджера) → **Добавить / обновить**.
   Передайте человеку адрес сайта, логин и пароль — он войдёт с любого компьютера или телефона.

С этого момента все работают с **одной общей базой**: проект, созданный на замере,
через несколько секунд виден в офисе.

## Часть 5. Автообновление сайта из GitHub по FTP (один раз, 5 минут)

Как это работает после настройки: любая правка, которую я вношу и отправляю в GitHub,
автоматически собирается и заливается на хостинг. Вам ничего скачивать и загружать не нужно —
через 3–5 минут после пуша обновлённый сайт уже на вашем адресе.

### 5.1. Узнать пароль FTP

Пароль FTP — тот же, что выдан для доступа к хостингу (есть в письме
«Услуга хостинга активирована»). Если он потерян или вы хотите отдельный:
панель управления → раздел **FTP-пользователи** → выберите пользователя
→ **Изменить** → задайте новый пароль → **Ok**.

### 5.2. Добавить один секрет в GitHub

1. Откройте **https://github.com/silovr709-dotcom/Calculator/settings/secrets/actions**
   (репозиторий → **Settings** → слева **Secrets and variables** → **Actions**).
2. Нажмите **New repository secret**.
3. **Name:** `FTP_PASSWORD`
   **Secret:** ваш пароль FTP (без пробелов по краям).
4. **Add secret**.

Больше ничего добавлять не надо: адрес сервера, логин и папка уже прописаны в workflow:

| Параметр | Значение по умолчанию |
|---|---|
| Сервер FTP | `u3683615.isp.regruhosting.ru` |
| Логин FTP | `u3683615` |
| Папка сайта | `/www/u3683615.isp.regruhosting.ru/` |
| Адрес для проверки | `https://u3683615.isp.regruhosting.ru` |

Если что-то из этого изменится (сменили хостинг, завели отдельного FTP-пользователя,
подключили домен) — добавьте секреты `FTP_SERVER`, `FTP_USERNAME`, `FTP_DIR`, `SITE_URL`:
они перекрывают значения по умолчанию.

### 5.3. Запустить первую выкладку

1. Откройте **https://github.com/silovr709-dotcom/Calculator/actions**
2. Слева выберите **Deploy to hosting (FTP)**.
3. Справа **Run workflow** → ветка `arena/01a0ee6f-calculator` (или `main`).
   * Можно сначала поставить галочку **dry run** — тогда система только покажет,
     что будет залито, ничего не меняя на хостинге.
4. Дождитесь зелёной галочки. В конце журнала будет строка
   «Сайт обновлён и отвечает: https://u3683615.isp.regruhosting.ru».

### 5.4. Дальше всё само

Выкладка запускается автоматически при каждом пуше в ветки `main`
и `arena/01a0ee6f-calculator` (правки только в документации сайт не трогают).
Порядок работы такой:

1. вы пишете мне, что поправить;
2. я вношу правки и отправляю их в GitHub;
3. GitHub собирает приложение и заливает его на ваш хостинг;
4. через 3–5 минут вы обновляете страницу сайта (**Ctrl + F5**) и видите изменения.

Статус последней выкладки всегда виден на вкладке **Actions**: зелёная галочка — готово,
красный крест — откройте запуск и посмотрите, на каком шаге ошибка.

### 5.5. Что выкладка не трогает

* папку с данными `recept-data` (проекты, клиенты, пользователи, резервные копии);
* файл `api/config.php`, если вы его создавали;
* папку `.well-known` (подтверждение SSL-сертификата).

То есть обновление кода никогда не стирает вашу базу.

### 5.6. Если выкладка падает

| Сообщение в журнале | Что делать |
|---|---|
| «Выкладка пропущена: нет секрета FTP_PASSWORD» | Секрет не добавлен или назван иначе — проверьте имя: ровно `FTP_PASSWORD` |
| `530 Login authentication failed` | Неверный пароль или логин FTP. Смените пароль в разделе **FTP-пользователи** и обновите секрет |
| `ECONNREFUSED` / таймаут соединения | Хостинг не принимает FTP с внешних адресов или нужен FTPS — добавьте секрет `FTP_PROTOCOL` со значением `ftps` |
| Файлы залиты, но сайт не ответил | Откройте `https://u3683615.isp.regruhosting.ru/api/index.php?r=check` — страница назовёт причину |
| Залилось не туда | Проверьте папку в панели и при необходимости задайте секрет `FTP_DIR` (со слешем в конце) |

## Часть 6. «Подключение не защищено», HTTPS и свой домен

### 6.1. Почему браузер ругается на техническом адресе

На адресе вида `u3683615.isp.regruhosting.ru` браузер показывает
«Подключение не защищено» / «сертификат относится к *.hosting.reg.ru».
Это нормально и исправить на техническом адресе нельзя:

* сервер отдаёт общий сертификат хостинга, выписанный на другое имя;
* бесплатный Let's Encrypt для технических доменов `*.regruhosting.ru` **не выпускается** —
  reg.ru прямо пишет, что технологический домен нельзя выбирать при выпуске, иначе ошибка;
* сертификат выпускается только на **свой домен**, привязанный к хостингу.

Что делать прямо сейчас: нажать **«Дополнительно» → «Перейти на сайт (небезопасно)»**.
Браузер запомнит исключение. Данные при этом всё равно шифруются — браузер лишь
не может подтвердить, что сертификат принадлежит именно этому имени.

> Почему мы не отключаем HTTPS: по обычному `http://` браузеры запрещают доступ к камере,
> и перестанет работать сканирование QR-кодов на телефоне у замерщика.

### 6.2. Нормальное решение — свой домен (200–300 ₽ в год)

1. Личный кабинет reg.ru → **Домены** → **Зарегистрировать домен** (подойдёт любой, например `.ru`).
2. После регистрации: карточка домена → **Привязать к хостингу** → выберите свой хостинг.
3. ispmanager → **Сайты** → ваш сайт → **Изменить**:
   * в поле **Доменное имя** добавьте новый домен (или впишите его в **Псевдонимы**);
   * поставьте галочки **Защищённое соединение (SSL)** и **Перенаправлять HTTP-запросы в HTTPS**;
   * в блоке **SSL-сертификат** выберите **Новый Let's Encrypt сертификат** → **Ok**.
4. Выпуск занимает от нескольких минут до часа. После этого сайт открывается по
   `https://ваш-домен.ru` с замком, без предупреждений, сертификат продлевается сам.
5. В приложении менять ничего не нужно: адрес сервера вычисляется от адреса страницы,
   данные и учётные записи остаются на месте.
6. Если включено автообновление из GitHub (часть 5) — добавьте секрет `SITE_URL`
   со значением `https://ваш-домен.ru`, чтобы проверка после выкладки шла по новому адресу.

### 6.3. Частые вопросы

* **Можно работать без своего домена?** Да. Предупреждение придётся один раз пропустить
  в каждом браузере и на каждом телефоне.
* **Данные в безопасности?** Да: вход по паролю, сессии и общая база работают одинаково,
  трафик шифруется в обоих случаях.
* **Старый адрес перестанет работать?** Нет, технический адрес остаётся рабочим.

## Часть 7. Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| Открывается список файлов вместо приложения | Файлы лежат в подпапке. Переместите содержимое в корень папки сайта. |
| Белый экран, в консоли браузера 404 на `assets/...` | То же самое: файлы не в корне сайта. |
| Внизу слева нет пункта «Сервер», приложение работает как раньше | Не загрузилась папка `api` или выключен PHP. Проверьте `…/api/index.php?r=health`. |
| `api/index.php?r=health` отдаёт 500 | Версия PHP ниже 8.0. ispmanager → Сайты → PHP → 8.1. |
| «Нет доступной папки для данных» | Создайте в менеджере файлов папку `recept-data` рядом с папкой сайта (в каталоге `www`'s родителе, т. е. в корне аккаунта) и поставьте права 755. |
| «Не удалось записать данные на диск» | Кончилось место на тарифе. Удалите старые копии в `recept-data/backups`. |
| Проект с фотографиями не сохраняется | В файле `.user.ini` поднимите `post_max_size` и `upload_max_filesize` до `256M`. |
| После обновления видна старая версия | Обновите страницу с очисткой кэша: Ctrl+F5. |
