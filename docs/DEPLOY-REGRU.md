# Запуск калькулятора на хостинге reg.ru

Инструкция рассчитана на **виртуальный хостинг** (PHP, панель управления, FTP) — тот тариф, где нет Node.js.
После установки приложение работает как обычный сайт: сотрудники заходят по логину и паролю,
проекты и клиенты хранятся **на вашем хостинге**, а не в браузере.

Весь код для этого уже в репозитории:

| Что | Где | Зачем |
|---|---|---|
| Приложение | `app/` | То, что видит пользователь |
| Серверная часть | `server/api/*.php` | Вход, общая база, резервные копии, передача по QR |
| Настройки Apache и PHP | `server/.htaccess`, `server/.user.ini` | HTTPS, сжатие, лимиты на размер данных |
| Сборщик пакета | `tools/pack-hosting.mjs` | Делает папку и zip, готовые к загрузке |
| Проверка API | `server/tests/api.test.mjs` | Прогоняет сервер на настоящем PHP, без установки PHP |

---

## Коротко: пять шагов

1. В панели reg.ru включить **PHP 8.0+** и создать сайт.
2. На своём компьютере собрать пакет: `cd app && npm install && npm run build:hosting`.
3. Залить содержимое `release/site` (или архив `release/recept-site.zip`) в корень сайта.
4. Открыть сайт → экран **«Первый запуск»** → придумать логин и пароль владельца.
5. В разделе **«Сервер»** добавить сотрудников. Готово.

---

## Шаг 1. Подготовка хостинга

1. Войдите в личный кабинет reg.ru → **Услуги → ваш хостинг → Панель управления**.
2. Создайте сайт (в ISPmanager это **WWW-домены → Создать**). Пока нет своего домена, используйте
   технический адрес, который хостинг выдаёт автоматически — приложение к адресу не привязано,
   домен можно подключить потом без потери данных.
3. В настройках сайта выберите **PHP 8.0 или новее** (подойдёт 8.1–8.3), режим **PHP-FPM**.
4. Проверьте, что включён модуль **mod_rewrite** — на reg.ru он включён по умолчанию.
5. Запишите данные FTP: сервер, логин, пароль (раздел **FTP-пользователи**).

Ничего больше: база данных MySQL не нужна, всё хранится в файлах.

## Шаг 2. Сборка пакета

На компьютере, где установлен Node.js 20+:

```bash
git clone https://github.com/silovr709-dotcom/Calculator.git
cd Calculator/app
npm install
npm run build:hosting
```

В папке `release/` появятся:

* `release/site/` — содержимое корня сайта;
* `release/recept-site.zip` — то же самое одним файлом (~2–3 МБ).

## Шаг 3. Загрузка на хостинг

**Вариант А — через менеджер файлов панели (проще).**
Загрузите `recept-site.zip` в корневую папку сайта (`public_html`, `www/ваш-домен` или подобную)
и распакуйте её средствами панели. Архив сам распакуется «в текущую папку».

**Вариант Б — через FTP (FileZilla).**
Подключитесь по данным из шага 1 и скопируйте **всё содержимое** `release/site` в корень сайта.
Важно: в FileZilla включите показ скрытых файлов (**Сервер → Принудительно отображать скрытые файлы**),
иначе не зальются `.htaccess` и `.user.ini` — без них не будет HTTPS-редиректа и больших загрузок.

После загрузки в корне сайта должно быть так:

```
index.html
assets/…
api/index.php
api/core.php
api/.htaccess
.htaccess
.user.ini
```

## Шаг 4. Первый запуск

1. Откройте сайт в браузере.
2. Появится экран **«Первый запуск»** — создайте учётную запись владельца
   (логин латиницей, пароль не короче 8 символов). Эта учётка получает полные права.
3. Приложение сразу откроется с пустой общей базой.

Проверка, что сервер отвечает: откройте `https://ваш-сайт/api/index.php?r=health` —
должен вернуться JSON вида `{"ok":true,"php":"8.2.…","needsSetup":false}`.

## Шаг 5. Сотрудники

Раздел **«Сервер»** в левом меню (виден, когда приложение работает на хостинге):

* **Сотрудники** — добавить логин, имя, пароль, права («Владелец» или «Сотрудник»).
  Передайте человеку логин и пароль, он войдёт с любого компьютера или телефона.
* **Мой пароль** — смена собственного пароля.
* **Резервные копии** — список копий базы и восстановление в один клик.

Все работают с **одной общей базой**: проект, созданный замерщиком на планшете,
через несколько секунд виден в офисе.

## Как это работает внутри

* Правки копятся в браузере и уходят на сервер пачкой через 1,5 секунды после последнего изменения —
  индикатор состояния виден в разделе «Сервер» и в меню.
* Если связь пропала, работа продолжается: правки лежат в браузере и уходят автоматически,
  когда связь вернётся.
* Если двое сохранили одновременно, сервер сообщает о расхождении, а приложение сливает версии:
  по каждому проекту и клиенту побеждает более свежая правка, ничего не теряется.
* Перед каждым сохранением (но не чаще раза в 10 минут) сервер складывает копию базы в архив.
  Хранятся последние 60 копий.
* Данные лежат в папке `recept-data` **рядом** с папкой сайта — из браузера она недоступна.
  Если хостинг не разрешает запись за пределами сайта, папка создаётся внутри и закрывается `.htaccess`.
* Пароли хранятся только в виде хэша (`password_hash`), после 10 неудачных попыток вход
  с этого адреса блокируется на 10 минут.

### Адреса API (для справки и отладки)

| Запрос | Что делает |
|---|---|
| `GET api/index.php?r=health` | Проверка, что сервер жив |
| `GET api/index.php?r=session` | Кто вошёл и какая версия базы |
| `POST api/index.php?r=login` | Вход |
| `GET api/index.php?r=state` | Выгрузить всю базу |
| `PUT api/index.php?r=state` | Сохранить базу (с проверкой версии) |
| `GET api/index.php?r=backups` | Список резервных копий |
| `GET api/index.php?r=share&id=…` | Открыть проект, переданный по QR |

## Обновление версии

1. `git pull` и снова `npm run build:hosting`.
2. Залить содержимое `release/site`, **перезаписав** старые файлы.
3. Папку `recept-data` и файл `api/config.php` (если создавали) не трогать — данные сохранятся.

Старые файлы `assets/*.js` можно удалить: имена новых отличаются хэшем.

## Подключение своего домена (когда купите)

1. В панели reg.ru добавьте домен к сайту (**WWW-домены → ваш сайт → Домены**).
2. В DNS домена пропишите A-запись на IP хостинга (если домен тоже на reg.ru — делается в два клика).
3. Закажите бесплатный сертификат **Let's Encrypt** в разделе SSL.
4. Ничего в приложении менять не нужно: оно определяет адрес API от адреса страницы.
   Принудительный переход на HTTPS уже прописан в `.htaccess`.

## Если что-то пошло не так

| Симптом | Причина и лечение |
|---|---|
| Белый экран, в консоли 404 на `assets/…` | Файлы залиты не в корень сайта, а в подпапку. Переложите содержимое `release/site` в корень. |
| «Сервер недоступен», приложение работает как раньше (только в браузере) | Не залита папка `api` или PHP отключён. Проверьте `…/api/index.php?r=health`. |
| HTTP 500 на `api/index.php` | Версия PHP ниже 8.0 либо нет прав. Поставьте PHP 8.x, права: папки 755, файлы 644. |
| «Нет доступной папки для данных» | Хостинг запретил запись. Создайте папку `recept-data` рядом с папкой сайта и дайте права на запись (755). |
| «Не удалось записать данные на диск» | Кончилось место на тарифе или квота. Удалите старые копии в `recept-data/backups`. |
| Большой проект с фото не сохраняется (413) | Поднимите лимиты в `.user.ini`: `post_max_size` и `upload_max_filesize` до 256M. |
| Не видно `.htaccess` при загрузке | Включите показ скрытых файлов в FTP-клиенте. |

## Проверка серверной части без хостинга

PHP на компьютер ставить не нужно — тест поднимает настоящий PHP 8.2 внутри Node:

```bash
cd server/tests
npm install
npm test
```

Скрипт прогоняет вход, права, сохранение базы, конфликт версий, сотрудников,
резервные копии и передачу по QR.
